# Тест-стратегия для проекта SauceDemo

## 1. Введение
Данный документ описывает подход к тестированию учебного веб-приложения SauceDemo (интернет-магазин). Цель — обеспечить проверку основного функционала (авторизация, каталог, корзина, оформление заказа) и выявить критические дефекты.

## 2. Область тестирования (Scope)
**Входит в тестирование:**
* Функциональное тестирование (логин, корзина, чекаут).
* Тестирование UI (соответствие макету, расположение элементов).
* Кросс-браузерное тестирование (Chrome, Firefox, Edge).
* Базовое API-тестирование (проверка ответов сервера).
* Тестирование специальных пользователей (problem_user, error_user и др.).

**Не входит (Out of scope):**
* Нагрузочное тестирование (не проводится на данном этапе).
* Тестирование безопасности (кроме базовых проверок на XSS/SQLi).

## 3. Виды тестирования
* **Smoke:** Проверка работоспособности системы после деплоя (успешный вход, отображение каталога).
* **Функциональное:** Проверка бизнес-логики по готовым тест-кейсам.
* **Регрессионное:** Проверка, что новые фиксы не сломали старое (прогон всех 41 тест-кейса).
* **Исследовательское:** Свободное тестирование для поиска неочевидных багов.

## 4. Окружение
* **Браузеры:** Google Chrome 120+, Mozilla Firefox 120+, Microsoft Edge.
* **ОС:** Windows 10/11.
* **Инструменты:** Chrome DevTools, Postman, Jira (для учебного процесса — Markdown).

## 5. Риски и приоритеты
* **Высокий приоритет:** Авторизация, процесс оформления заказа (Checkout), добавление в корзину. Ошибки здесь блокируют покупку.
* **Средний приоритет:** Сортировка, фильтрация, отображение изображений.
* **Низкий приоритет:** Опечатки в тексте, вёрстка на специфических разрешениях.

## 6. Критерии входа и выхода
* **Вход (Start):** Сборка развернута на тестовом стенде, есть требования, тест-кейсы актуализированы.
* **Выход (Exit):** Все запланированные тест-кейсы пройдены, критические и блокирующие баги исправлены, регрессия пройдена успешно.

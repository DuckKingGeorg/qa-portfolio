# Тест-стратегия для проекта SauceDemo

## 1. Введение
Данный документ описывает стратегию тестирования учебного веб-приложения SauceDemo (интернет-магазин).
Цель тестирования: оценить качество приложения, проверить корректность основных пользовательских сценариев, выявить и задокументировать дефекты.
Основное внимание уделяется авторизации, работе каталога товаров, корзине и процессу оформления заказа.

## 2. Область тестирования (Scope)
**Входит в тестирование (In scope)**
* Функциональное тестирование: проверка авторизации, каталога товаров, добавления и удаления товаров из корзины, оформления заказа.
* UI-тестирование: проверка отображения элементов интерфейса, их расположения и соответствия ожидаемому поведению.
* Негативное тестирование: проверка реакции приложения на некорректные данные и нестандартные действия пользователя.
* Тестирование специальных пользователей: проверка поведения приложения под учётными записями problem_user, error_user, performance_glitch_user, visual_user, locked_out_user.
* Адаптивное тестирование: проверка отображения интерфейса на различных разрешениях экрана.
* Исследовательское тестирование: поиск дефектов за пределами заранее подготовленных тест-кейсов.

**Не входит (Out of scope):**
* Полноценное нагрузочное и стрессовое тестирование.
* Полноценное тестирование безопасности и проведение профессионального аудита защищённости.
* Полноценное API-тестирование.
* Автоматизированное тестирование всех пользовательских сценариев.
* Полноценное кросс-браузерное тестирование.

## 3. Виды тестирования
* Smoke-тестирование: быстрая проверка основных функций приложения после изменений: авторизация, открытие каталога, доступность корзины.
* Функциональное тестирование: проверка работы функций приложения по подготовленным тест-кейсам.
* Регрессионное тестирование: повторная проверка ранее протестированных функций после изменений или исправления дефектов.
* Негативное тестирование: проверка обработки некорректных данных и действий пользователя.
* UI-тестирование: проверка корректности отображения элементов интерфейса.
* Исследовательское тестирование: свободное исследование приложения для обнаружения неочевидных дефектов.

## 4. Окружение
* Операционная система: Windows 10.
* Браузер: Google Chrome 157.0.8103.80 (64 бит).
* Тестовое приложение: https://www.saucedemo.com/

**Тестовые учётные записи:** 
* standard_user
* problem_user
* performance_glitch_user
* error_user
* visual_user
* locked_out_user

**Инструменты:**
* Chrome DevTools — анализ интерфейса и поведения веб-приложения.
* GitHub — хранение тестовой документации и результатов тестирования.
* Markdown — оформление тест-кейсов, чек-листов и баг-репортов.

## 5. Риски и приоритеты
* **Высокий приоритет:** Авторизация, процесс оформления заказа (Checkout), добавление в корзину. Ошибки здесь блокируют покупку.
* **Средний приоритет:** Сортировка, фильтрация, отображение изображений.
* **Низкий приоритет:** Опечатки в тексте, вёрстка на специфических разрешениях.

## 6. Критерии входа и выхода
* **Вход (Start):** Сборка развернута на тестовом стенде, есть требования, тест-кейсы актуализированы.
* **Выход (Exit):** Все запланированные тест-кейсы пройдены, критические и блокирующие баги исправлены, регрессия пройдена успешно.
